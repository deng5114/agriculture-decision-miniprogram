# 农业作物智能决策小程序系统设计

## 1 项目目标

本项目面向农村种植场景，提供种植信息填报、作物规则推荐、历史市场行情、灾害预警、农技审核和区域统计功能。第一版以可演示、可解释、可测试为目标，使用规则驱动推荐和可替换的模拟数据，不把系统描述为已经训练完成的机器学习模型。

## 2 总体架构

```text
微信小程序前端
        |
        | HTTPS REST API
        v
Node.js + Express 后端
        |
        v
MySQL 数据库
```

前端负责页面展示、表单交互、权限入口和结果播报；后端负责身份识别、角色权限、数据归属校验、推荐计算、审核流转和统计；数据库保存用户、地块、种植记录、规则、行情、预警和操作日志。

## 3 用户角色

| 角色 | 主要功能 | 数据范围 |
|---|---|---|
| 种植农户 | 填报地块、获取推荐、查看行情和预警 | 只能访问本人地块和种植记录 |
| 畜牧/渔业从业者 | 提交配套资源和合作信息 | 只能维护本人提交的信息，公开前必须审核 |
| 农技工作人员 | 审核内容、维护作物和灾害规则 | 不能修改管理员权限和核心系统配置 |
| 区域管理者 | 查看区域统计、管理账号和角色 | 关键操作必须保留操作日志 |

后端每个受保护接口都必须校验用户角色和数据归属，不能只依赖前端隐藏按钮。

## 4 页面与导航

### 公共页面

- 登录页：演示登录和角色识别
- 权限说明页：说明相机、麦克风等权限用途

### 农户端

- 首页：我的地块、快捷填报、推荐、预警
- 地块填报页：文字、语音、拍照三种入口
- 识别确认页：展示候选字段，允许修改后确认
- 推荐结果页：Top 3、匹配分、推荐理由和风险
- 市场行情页：作物、区域、年份筛选和趋势图
- 灾害预警页：等级、影响、措施和数据来源
- 我的记录页：草稿、待审核、已通过、已驳回

### 农技端

- 待审核列表
- 记录详情
- 通过/驳回审核
- 作物规则和灾害规则维护

### 管理员端

- 区域统计
- 用户和角色管理
- 审核概况
- 操作日志

## 5 核心业务状态

```text
草稿 -> 待审核 -> 已通过
                  |
                  v
                公开展示/统计

待审核 -> 已驳回 -> 草稿 -> 待审核
```

- 草稿：农户可以编辑、删除和提交。
- 待审核：农技人员可以查看、通过或驳回。
- 已通过：允许按权限展示和参与统计。
- 已驳回：必须保留审核意见，农户修改后重新提交。

## 6 推荐规则

```text
推荐分 = 0.30×土壤适配度
       + 0.25×气候适配度
       + 0.20×市场稳定度
       + 0.15×经验匹配度
       + 0.10×成本适配度
```

各指标归一化为 0—100 分。土壤类型或生长温度明显不匹配时淘汰作物；价格波动大、成本超预算或经验不足时降低对应分数，并在结果中显示风险原因。

## 7 多模态识别原则

语音和图片识别结果只能作为候选字段，不能直接写入数据库。流程固定为：

```text
输入语音/图片 -> 生成候选结果 -> 用户确认或修改 -> 字段校验 -> 保存
```

识别失败时必须提供重试和手动录入入口。

## 8 第一版范围边界

第一版不自行训练机器学习模型，也不实现农产品交易、溯源、物联网传感器、在线聊天和独立养殖决策。天气采用 Open-Meteo，语音与植物图片识别采用可替换的百度智能云适配层；课程市场种子数据仍明确标注为模拟数据。
